## Выполнение задания

### 1. Одиночное дерево решений

Сначала обучен `DecisionTreeClassifier` как baseline.

Результат на test:

```text
Accuracy = 0.8000
F1       = 0.6667
ROC AUC  = 0.7619
```

Одиночное дерево способно хорошо подстроиться под обучающие данные, но имеет высокий разброс: небольшое изменение выборки может заметно изменить структуру дерева.

### 2. Random Forest

Случайный лес объединяет множество деревьев, обученных на разных bootstrap-выборках и случайных подмножествах признаков.

На тех же данных получено:

```text
Accuracy = 0.9000
F1       = 0.8235
ROC AUC  = 0.9630
```

Прямое сравнение:

| Модель | Accuracy | F1 | ROC AUC |
|---|---:|---:|---:|
| Decision Tree | 0.8000 | 0.6667 | 0.7619 |
| Random Forest | **0.9000** | **0.8235** | **0.9630** |

Случайный лес значительно лучше одиночного дерева по всем основным метрикам.

### 3. Настройка гиперпараметров

Настраиваются три основных параметра:

- `n_estimators` — количество деревьев;
- `max_depth` — максимальная глубина дерева;
- `min_samples_leaf` — минимальное число объектов в листе.

Проверено **18 комбинаций** параметров с **5-fold cross-validation**.

Лучший результат:

```text
n_estimators = 100
max_depth = None
min_samples_leaf = 1
CV F1 = 0.7211
```

Перебор показал, что для данного небольшого датасета усложнение ограничений дерева не улучшает результат.

### 4. Почему выбрано 100 деревьев

В сетке сравнивались разные значения `n_estimators`. Увеличение количества деревьев до 200 не улучшило CV F1 относительно 100.

Поэтому выбрано:

```text
n_estimators = 100
```

Это достаточное количество деревьев для стабилизации ансамбля на данном датасете без лишних вычислительных затрат.

### 5. Сравнение tuned и default модели

Итоговые параметры GridSearch фактически близки к стандартной конфигурации `RandomForestClassifier`.

Это важный результат: гиперпараметры не были просто оставлены по умолчанию — был выполнен реальный перебор, который показал, что дополнительные ограничения глубины и размера листа не дают выигрыша на текущих данных.

### 6. Важность признаков

Получена встроенная impurity-based важность через:

```python
model.feature_importances_
```

Наиболее важные признаки:

| Признак | Важность |
|---|---:|
| `income` | **0.2686** |
| `tenure_months` | **0.2189** |

Эти два признака сильнее остальных участвуют в разделениях деревьев ансамбля.

Важно: feature importance показывает полезность признака для предсказаний модели, но **не означает причинно-следственную связь**.

### 7. Диаграмма важности

Столбчатая диаграмма сохранена в:

```text
results/feature_importance.svg
```

Она позволяет визуально сравнить вклад всех шести признаков.

### 8. Эксперимент удаления слабых признаков

Признаки сортируются по важности, после чего выполняется последовательное удаление наименее важных признаков.

Ключевое правило эксперимента: решение об удалении оценивается по cross-validation на обучающей части данных, а test сохраняется для финальной проверки.

Наиболее интересный результат получен после совместного удаления:

```text
age
support_calls
```

Метрики:

```text
CV F1:   0.7211 -> 0.7272
Test F1: 0.8235 -> 0.8421
```

То есть удаление этих двух признаков не ухудшило качество. Наоборот, на данном разбиении результат немного улучшился.

После удаления следующего признака CV-качество уже начинает заметнее снижаться.

### 9. Какие признаки можно исключить

По результатам эксперимента кандидатами на исключение являются:

```text
age
support_calls
```

Для данного датасета они дают небольшой дополнительный вклад и могут быть исключены без наблюдаемой потери качества.

При этом этот вывод относится именно к текущему набору данных и процедуре валидации. Он не означает, что эти признаки бесполезны во всех задачах.

Случайный лес оказался заметно устойчивее и точнее одиночного дерева решений. Кросс-валидация показала, что для данного датасета 100 деревьев достаточно, а дополнительные ограничения глубины и размера листьев не улучшают качество.
